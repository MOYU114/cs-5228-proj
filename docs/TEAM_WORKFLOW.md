# 四人分工与交接流程

## 任务边界

团队当前阶段的交付是课程要求的 **progress report**（团队内部可称 proposal）：约 10–15 页幻灯片，导出 PDF，课程说明建议在 2026 年 10 月 4 日前提交。四个角色暂以 A、B、C、D 标识，待团队填入姓名；候选方案数量尚未确定，B 和 C 是两名实验执行者，并不意味着固定两种方案。

| 角色 | 主责 | 交付物 | 交给谁 |
| --- | --- | --- | --- |
| A：EDA 与选型分析 | 审计字段、分布、异常值、类别规范化、时间漂移与辅助数据可连接性；提出候选方案和比较理由 | `notebooks/` 中的 EDA、关键图表、候选方案清单及选择依据 | B/C 使用清洗规则和候选清单；D 使用可核实图表和解释 |
| B：方案测试 | 与 C 共用固定验证协议和 RMSE；负责分配到的候选实验、参数记录、误差分析 | `experiments/` 中的可复现实验入口、配置、结果摘要 | D 汇总记录；A 判断方案是否值得继续 |
| C：方案测试 | 与 B 对齐数据切分、基线和指标；负责其他分配到的候选或同方案的独立比较/消融 | 同上；与 B 的结果可直接横向比较 | D 汇总记录；A 判断方案是否值得继续 |
| D：测试记录与文档 | 维护实验台账、核对复现信息、整理失败结果与图表，撰写进度报告和后续工作计划 | `proposal/experiments/` 中的台账与摘要、`proposal/main.md` 中的报告草稿 | 全员审阅事实与结论 |

## 共同约定

1. **先统一协议，再比较方案。** A、B、C、D 共同确认训练/验证月份、RMSE 计算、基线和实验编号；正式比较不得各自换切分。
2. **候选数量随证据调整。** A 给出有理由的候选清单，B/C 按优先级领取实验；一个人可以测多个方案，也可以共同验证同一方案。未跑通的候选保留记录，不把它写成有效结果。
3. **每次实验留可追溯记录。** 使用 [`EXPERIMENT_RECORD_TEMPLATE.md`](EXPERIMENT_RECORD_TEMPLATE.md)，至少记录数据切分、特征、方法、参数、随机种子、RMSE、运行命令、代码版本和结论。D 负责完整性核对，实验者对数值负责。
4. **结果与主张对应。** 进度报告中的每个数字和图表都指向一次已记录实验；A 解释数据现象与选型，B/C 解释方法和误差，D 统一表述。
5. **短会同步。** 每轮实验后用简短记录更新：已完成、发现、下一实验、阻碍。涉及验证协议或数据清洗的变更由全员确认，并标记为新实验版本。

## 交接门槛

- A → B/C：字段与清洗规则可执行；候选方案说明输入特征、预期收益和要验证的假设。
- B/C → D：有运行命令、配置、RMSE 和对照基线；注明失败或异常结果，不能只给最佳分数截图。
- D → 全员：Markdown 工作稿标明尚缺的证据、图表来源与数据口径；全员核对后再制作幻灯片 PDF。
