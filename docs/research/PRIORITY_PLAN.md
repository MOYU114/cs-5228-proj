# 最值得尝试的清单：以未来租金 RMSE 为目标

更新：2026-09-26。**我的优先顺序是：TabM → 时间调制 TabM → TabICLv2 → TabPFN-3.5 → ModernNCA。** 先建立可靠的单模型，再检验少量模型的互补融合。这是结合 EDA、论文机制和独立审查后的实验投资顺序；没有本项目模型成绩，不能称为已验证的精度榜或承诺 Kaggle 最高名次。

本文件是当前决策入口。[详细调研](METHOD_RESEARCH.md) 解释来源与实现，[idea-evaluator](IDEA_EVALUATION.md) 保存五维评估，[EDA](../EDA_REPORT.md) 提供本地事实。GPU 可用，成本只是软偏好；本轮仍未训练或提交。

## 1. 为什么这样排序

原可行性排序把 TabICLv2 放在时间调制之前；现在以未来 RMSE 为首要目标，将时间调制提前到第二位。N 编号保留原身份，不能按编号理解顺序。没有给模型虚构“预计 RMSE”或提升百分比。

| 顺位 | 方案与定位 | 数据规律给出的尝试理由 | 不应继续扩大投入的证据 |
| ---: | --- | --- | --- |
| **1** | **N1 TabM（2025）：首选主力与后续对照** | 150,000 条监督记录、9,406 个楼栋及非线性属性关系，为任务内学习提供动机；共享集成适合检验条件均值拟合，且可作为 N5 的同版底座 | 相同输入和未来窗口下弱于强树基线，或者远期均值偏差持续，新增表示/集成也未改善 |
| **2** | **N5 时间调制 TabM（2025）：优先检验远期风险** | 测试多数记录在训练截止后 6 个月以外；让属性映射随时间改变，直接对应最突出的部署难点 | 仅近期改善、远期 RMSE 变差；收益来自换主干/切分而非模块；对日期锚点和谐波容量过度敏感 |
| **3** | **N2 TabICLv2（2026）：预训练路线及融合候选** | 不同先验可能补充 TabM 的误差；可检验充分历史上下文和近期上下文的差异 | 统一时间窗口没有单模型增益，也没有实际可验证的融合增益 |
| **4** | **N4 TabPFN-3.5（2026）：另一条强基础模型候选** | 最新预训练能力值得直接比较，冻结权重后可另测微调；当前证据未证明它在本题大表时间外推上优于 TabM/N2 | 使用相同合法信息后，单模与融合都无增量；不能借其他服务版本的成绩证明本地模型 |
| **5** | **N3 ModernNCA（2025）：针对相似交易的补充路线** | 测试 99.796% 行属于已见楼栋，历史相似交易有利用价值 | 邻居价格过时导致远期回拉；相对简单历史统计/TabM没有增量；检索改善不足以支撑真实资源投入 |

来源：[TabM](https://proceedings.iclr.cc/paper_files/paper/2025/hash/c1ba41c694834aeef91ae161711d4939-Abstract-Conference.html)、[时间调制](https://papers.nips.cc/paper_files/paper/2025/hash/ddc20f403d0d296c87940393838d5971-Abstract-Conference.html)、[TabICLv2](https://arxiv.org/abs/2602.11139)、[TabPFN-3.5](https://arxiv.org/abs/2609.17895)、[ModernNCA](https://proceedings.iclr.cc/paper_files/paper/2025/hash/ecd294194d5155432aab533f7ce0f6fe-Abstract-Conference.html)。其中 TabPFN-3.5 是技术报告，不能冒称已有独立同行评审复现。

**N2 与 N4 的相对先后证据最弱，已有可用环境时可并行或互换。** 新版基础模型没有在这份 HDB 数据上与其他方案直接比较；先试 N2 是整体实验判断，不代表它预计更准。N5 没有排第一，是因为 150,000 行只有 51 个历史月份，复杂时间映射可能过拟合。N3 的历史目标范围限制也不证明必败：训练租金已覆盖 300–7,600 SGD，未来目标未知，真正要检查的是旧邻居水平是否形成系统性偏差。

经典方法继续保留：总体/分组均值、Ridge 用于诊断，CatBoost/LightGBM 是争分必须面对的强基线，不占五个现代候选。若干净验证中它们更好，最终选用它们或保留其融合贡献；发表年份不能成为牺牲真实分数的理由。

## 2. 以数据实际分布决定检查重点

下面由 [priority_profile.py](../../experiments/research/priority_profile.py) 读取已有月份计数实算，结果保存于 [priority_profile.json](../../experiments/research/priority_profile.json)。h 是相对训练截止 2025-03 的月份差，仅分析已给定日期，没有读取测试目标。

| 测试跨度 | 行数 | 占全部测试 |
| --- | ---: | ---: |
| h=0，共同边界月 | 380 | 0.760% |
| h=1–6 | 19,386 | 38.772% |
| h=7–16 | 30,234 | **60.468%** |

因此只优化一个近 6 个月验证集不充分。上述比例是描述性证据，**不转为模型样本权重或另造 Kaggle 指标**；本届 public/private 的划分方式和比例未核实，不能假定它们按月份切开。

楼栋已见率很高，因此主资源应放在“已见楼栋的未来租金水平与物业差异”；102 条新楼栋测试行仍要可靠回退，但不将新楼栋等权放大到与主要人群相同的选型权重。无 unit ID 且同 X 可有不同 y，模型应估计条件均值，不能把重复交易当作待复制答案。

月均租金变化及后期平台只说明需要测试时间稳定性，不证明未来继续上涨或平台延续。面积/楼龄相关也不是因果或单调约束的证据。高租金尾部可能贡献较大平方误差，具体贡献要从未来验证残差中计算；当前没有残差，不能提前写出其贡献率。

## 3. 评价指标：主分数与诊断分开

[项目指南](../PROJECT_TASK_GUIDE.md) 已记录本届 Kaggle 以 RMSE 评分。本轮尝试读取 [本届页面](https://www.kaggle.com/competitions/cs-5228-2610-project/overview) 未成功，因此这里沿用已有记录，不声称再次在线确认，更不借往届竞赛补齐规则。下一实验阶段执行前复核评价页面即可；本轮没有提交。

**唯一主指标是原租金尺度、完整验证窗口、每行等权的 RMSE，单位 SGD/月，越低越好：**

\[
\operatorname{RMSE}=\sqrt{\frac{1}{n}\sum_{i=1}^{n}(\hat y_i-y_i)^2}.
\]

不以 MAE、RMSLE、月均 RMSE、去尾后的 RMSE 取代主指标。MSE 与 RMSE 在同一组等权行上的排序相同，可用平方损失训练；神经网络标准化目标后必须反变换再评分。直接预测 log-rent 再取 exp 不保证得到原尺度条件均值，应作为独立实验处理。不要因租金常为整额就默认把预测舍入至 50，也不要仅为改善训练分布而删掉高租金样本。

| 诊断 | 必须报告什么 | 对应决策 |
| --- | --- | --- |
| 预测跨度 | 每月/每个 h、h=1–6 与 h=7–16 的 n、RMSE、MAE、平均残差 | 检查远期恶化是否被近期样本掩盖；残差定义 pred−truth，正值高估 |
| 高租金尾部 | 按该折训练 y 的 P95/P99 预先定阈值；报告验证组 n、RMSE、偏差及 SSE 占总 SSE 比例 | 识别平方误差来源；各模型使用同一组，主评分保留全部行 |
| 楼栋历史 | 每折已见/新楼栋、稀疏楼栋；近期裁窗丢失的楼栋另列 | 区别覆盖损失和时间适配；不能把全测试覆盖率套给各历史折 |
| 房屋属性 | 城镇、户型，必要时城镇×户型、面积/楼龄分箱的 n、RMSE、偏差 | 确认收益来自何种样本；小组数量少时不宣称稳定优势 |
| 稳定性 | 同行预测的误差差值、预先确定的必要重复种子、窗口排名翻转 | 区分可复现收益和随机波动，不以最佳 seed 选型 |

分组阈值/频数只用训练折拟合。诊断表不拼成任意加权“综合分”；也不强制各城镇、月份或尾部等权。对同一维度互斥且穷尽的分组，`sqrt(sum(SSE_g) / sum(n_g))` 应等于总体 RMSE；P95/P99 嵌套尾部和不同诊断维度不能直接相加。没有本地预测前，这些都是应填写的栏目，不能填估计分数。

## 4. 统一时间验证和晋级规则

窗口计数来自 [可复现结果](../../experiments/research/validation_windows.csv)：

| 窗口 | 训练范围 / 行数 | 验证范围 / 行数 | 职责 |
| --- | --- | --- | --- |
| V1 | 2021-01–2024-03 / 114,842 | 2024-04–2024-09 / 17,960 | 近期开发 |
| VL | 2021-01–2023-05 / 84,902 | 2023-06–2024-09 / 47,900 | 固定起点预测 16 个月，重点检验远期 |
| V2 | 2021-01–2024-09 / 132,802 | 2024-10–2025-03 / 17,198 | 冻结方案后的近期确认 |

V1 与 VL 验证标签重叠，不能拼接成 pooled RMSE、当作两个独立胜利或重复加权。两者训练长度和市场阶段也不同，VL 是压力场景，不能保证等同真实未来。V2 已用于 EDA，只能称算法确认窗，不是完全盲测；若继续据此调参，应明确改称开发窗。

建议预先登记以下规则，而不是看完结果再改标准：

1. 在每个外层训练段内部留完整月份做早停/调参；预处理、权重微调、候选库都服从同一截止日。选择完成后用完整外层训练段重拟合，不在未来预测期间更新真实租金。
2. V1 与 VL 并列报告。若一个候选在两窗都无优势、且融合也无增量，停止扩张；若两窗都改善，再检查改善是否稳定、是否由错误信息或不同预算造成。
3. 若窗口排名冲突，不宣布统一赢家。优先调查 VL 的 h=7–16 偏差和近期市场阶段差异，再做有限的训练段内部诊断；当前偏好更能控制远期风险的方案，但不以武断的固定权重覆盖巨大近期退步。
4. 固定特征组、超参数、上下文选择规则和融合算法后，再查看 V2。V2 若否定开发结论，记录失败并重新审视范围；不要一边调参一边继续称其“确认”。
5. 只有在下一阶段获得授权并完成验证后才考虑 Kaggle 核对；public 分数不用来反复拟合权重。最终保留单模型与融合的完整对照，最终方案由真实结果决定。

## 5. 我更看重的共同特征与最后一轮融合

比不断增加模型名字更值得优先完成的是相同、合法的输入方案：

| 顺序 | 输入/消融 | 依据与限制 |
| --- | --- | --- |
| A | 文本规范化 + 核心房屋字段 + 楼栋键 + 合法日历输入 | 户型原始 TVD 0.2394，规范化后 0.0101；去掉常量 FURNISHED/FEE，保留同 X 交易与原始目标尾部 |
| B | 楼栋表示、稀有/未知回退；全历史与近期训练/上下文的受控比较 | 高已见率提供动机；近期数据可能适应新水平，也可能损失楼栋覆盖，不能默认越新越好 |
| C | 经生效时间审计的 HDB 稳定位置/楼栋属性 | 规范化连接 100% 且无一对多；连接完整不代表时间安全或模型有收益，逐组消融 |
| D | 平滑历史楼栋/城镇×户型租金统计（可选适配） | 仅过去已知标签；训练行采用严格保序的折外统计，排除自己及同月不可确定先后的交易，验证固定在 cutoff；不能用全量训练组均值回填本行 |
| E | 设施或宏观信息 | 只有历史可得性证据成立才加入；计划站、快照状态和未来真实 COE/股票不能为追分直接连接 |

若做 D，稀疏组需收缩到更粗层级/总体，近期统计还要有样本数与缺失标记；其提升不能归给未经改动的原版模型。N3 已直接使用历史标签，额外统计同样需要消融。任何近期窗口或衰减系数都只在合法训练/开发流程中选择。

**最后值得验证的组合：N1 或 N5 + 最好树基线 + 一个通过验证的基础模型。** 这不是第六个主算法，也不是现在就把全部模型平均。先检查同行残差及真正融合后的 RMSE；算法家族不同不等于误差互补，两个模型共同低估未来市场时，平均也不会自动消除偏差。

首轮仅用少量非负、和为一的全局权重：`prediction = Σ w_m × prediction_m`。每个外层训练段内部生成严格向前的折外预测来学习权重，基础模型的调参/早停也只用相应内部训练信息；权重与模型随后固定用于该外层未来窗口。最终 V2 前冻结的是整套算法与选择规则，不用 V2 标签改权重。内部滚动预测可有多个起点，但同一行在权重拟合中应有预先定义且可追溯的处理，不能因重复预测而被无意放大。

不要把 V1/VL 的重叠标签堆起来拟合融合，再把同一数据的改善称为泛化证据；首轮也不做 16 套逐月权重或复杂 stacking。融合若没有稳定胜过最佳单模型，保留单模型。所有建议都可被真实时间验证推翻。

## 6. B/C 最佳尝试清单与当前交付边界

- [ ] 共用 A 的清洗版本、月级切分、原尺度 RMSE 和完整结果表，先完成均值/树基线。
- [ ] **第一轮：N1 TabM。** 对齐数值表示、楼栋回退和正确的多头损失，留下强主力与 N5 对照。
- [ ] **第二轮：N5 时间调制。** 同版静态/仅时间 embedding/调制三臂；每折重算时间统计，统一 Fourier 秒单位与月份锚点，检验周期容量和远期误差。
- [ ] **第三轮：N2 TabICLv2。** 固定回归 checkpoint，记录全量上下文与完整查询成本，微调另列。
