## 5. 写作前需要保持清楚的评估边界

1. **清洗先于切分。** `rent_cleaning.py` 的 ±2 月可比样本规则作用于全训练文件，时间边界附近的训练行删除决策可能使用验证期租金。严格时间验证需要先按时间切分，再仅用训练段制定和执行目标相关处理。
2. **验证样本发生筛选。** 原始标签分数恢复的是保留行的原始标签，不会恢复删除的 100 条验证记录。不能称 468.34 为全原始验证窗口或 Kaggle 得分。最终主指标应评估所有原始验证行。
3. **预处理拟合范围。** z-score 与 flat-model 词表在全训练文件上拟合后才切分。这是未来验证特征参与预处理拟合的问题，与租金标签泄漏需分别说明。严格协议应在每个训练窗口拟合后固定应用到验证。
4. **辅助信息时间可得性。** MRT 按开通月份过滤是一项已实现限制，但不证明每个预测 cutoff 当时已知全部后续开通日期。学校、商场是静态快照，楼栋信息的可得性也应说明。
5. **对照与消融尚未充分记录。** 没有共享严格协议的树模型比较、去预训练消融、辅助特征消融，不能断言 BERT 最优、预训练有效或某组特征带来多少增益。
6. **预测跨度和信息缺失。** 验证覆盖 12 个月，而测试最远 16 个月；缺少楼层、装修等单套房信息，相同输入对应不同租金。月索引不能保证外推未来市场变化。
7. **可复现资源尚不齐全。** 默认输入是仓库同级的 `../data`、`../data_preprocess`，本地未发现这两个目录；EDA 则默认仓库内 `data/`。模型权重、逐行验证预测、训练 histories 和测试提交未随当前 Git 工作树提供。正式交付应统一说明入口并补齐可获取资源。

修复验证协议和重新训练不属于本次模板整理；新结果产生后同时更新 VI、VII、摘要、结论及相关图表，避免混用旧分数。

## 6. 报告叙事与逻辑检查

定位：以方法应用和实证评估为主的课程项目（Technique/application），不主张新问题定义或原创 BERT 架构。以下是报告组织建议，区别于已完成实验。

| 环节 | 本项目内容 |
|---|---|
| 背景 | 租户和房东需要比较相近房屋的租金；测试月份主要位于历史标签之后 |
| 局限 1 | 原始类别拼写、楼栋事实缺失和设施信息异质，不能直接当作统一字段使用 |
| 局限 2 | 仅有粗粒度属性且相同输入有不同租金，需要学习字段组合，同时承认不可观测因素 |
| 核心想法 | 规范化并丰富房屋字段，以 masked-field pretraining 初始化表格 BERT，再微调预测月租金并进行时间外验证 |
| 挑战 1 → 模块 A | 形成一致且有来源的字段表示 → 规范化、辅助连接、特征生成与编码（IV） |
| 挑战 2 → 模块 B | 在混合字段上学习可迁移组合表示 → 字段 token、联合遮蔽、重建与回归（V） |
| 工作概括 1 | 数据审计及可追溯预处理（III–IV）；不宣称独创通用算法 |
| 工作概括 2 | 两阶段表格 BERT 的实现与已有实验（V） |
| 工作概括 3 | 有明确适用范围的时间外评估和误差分析（VI–VII）；最终结论强度取决于补齐的对照证据 |

时间外推和全窗口评估是独立的评估要求与当前限制，不包装成现有模型已经解决的模块。

逻辑检查：局限→核心想法、核心想法→挑战、挑战→方法、方法→工作概括，在上述限定范围内均能对应。需要关注的证据缺口为 2 项 MAJOR：严格时间切分下的全窗口结果、同协议基线/消融。若把两阶段学习写成已证明的性能改进，则该主张属于 CRITICAL，当前不能成立。
